# NX-CORE first user extension: nxmanageDD boot and capability supervision

Date: 2026-11-10.
Status: implementation under build and guest verification; whole-project Power12 qualification separate.
Owner: kernel/user/extension/nxmanageDD (NX-CORE source, USERLAND-compiled ELF).

## Ownership and boot architecture

K3 kernel/main.c has no knowledge of nxinit, service names, VFS paths,
startup arguments or test runners. The storage provider imports the
machine-only boot file /system/boot/entry into registry object
system.boot.entry. The kernel object bootstrap resolves that key into
/krnl/extension/nxmanageDD and launches one initial user-mode MACHINE task.
The extension reads /system/boot/manager.conf and starts /sbin/nxinit at
PLVL_ROOT, not at PLVL_MACHINE. Only kernel-created machine PID1 may spawn
an /sbin executable; all ROOT, USER, GUEST, and unrelated MACHINE callers
are rejected by the shared kernel spawn path before child allocation.

The extension is ordinary userland C compiled with USER_CFLAGS, the SDK
and user-mode syscall stubs. It is not linked into the freestanding kernel
image. Its location under kernel/user/extension names source/release
ownership, not execution privilege or direct access to kernel internals.
CPU idle tasks remain kernel scheduling entities. The lifecycle controller
has exactly one authoritative owner (PID1), avoiding competing per-CPU
authorities. Future parallel workers must remain subordinate and capability
restricted; no independent MACHINE manager for each CPU is authorized.

## Boot file and trust policy

The source is user/sys/boot; the built root filesystem places all files under
/system/boot, a tree whose writes are already MACHINE-only in the VFS ACL.
The /sys/services ELF tree is additionally MACHINE-only for writes.

- entry: one canonical executable path interpreted by the generic kernel
  initial-ELF entry, not a table of service names.
- manager.conf: init=/sbin/nxinit, read only by the PID1 extension.
- services.conf: manifest parsed only by nxinit. Records use
  name|mode|absolute-executable|arguments|optional-srv-key. Protocol v2
  registers a unique NAME before each REGISTER over the same PORT queue.
  Modes lock (persistent), once (real successful completion before ACK),
  and debug (mdebug-only asynchronous once). Named identities are primary;
  numeric slots remain secondary compatibility IDs.
- profile: 0 or 1 with newline, generated by the integration build using
  MDEBUG. Switching profile rebuilds rootfs, never recompiles kernel code.

The obsolete /etc/init.cfg is not authoritative. The current manifest
has 14 named policies including dedicated notification, execution, timer,
NXPAX, compositor, keyboard and pointer services; the environment one-shot,
supervised desktop, launcher, shell, isolated headless mdebug runner and
ROOT/MACHINE capability probe. These are NOT 14 daemon binaries.

## Authority and transport

The kernel supplies its existing 32-cell buffered PORT object queue. A
single 88-byte descriptor carries the kernel-stamped sender PID; new
OBJ_CTL_PORT_TRY_RECV=14 dequeues from the SAME locked queue as the existing
blocking object read and returns -EAGAIN for empty, -EPIPE for closed.
No duplicate userland ring, faux dispatcher, or invented IPC transport exists.

The generic acquisition-only OS1_PORT_CREATE_PRIVATE flag limits private
PORT creation to MACHINE. The generic object namespace reserves
OS1nx_machine_* receiver creation to MACHINE, and OS1nx_* receiver
creation to ROOT/MACHINE; client SEND acquisition remains possible on
ordinary public services. This prevents USER/GUEST service-port squatting
during service restarts. Full endpoint-in-registry migration remains open.
PID1 creates the private endpoint and a transfer-capable sender handle.
nxinit allocates its own handle table, sends an authenticated HELLO through
the existing bounded process mailbox to its actual parent, and receives
a cap_grant result for the WRITE-only PORT handle. It validates cap_query
type and exact rights. Transfer/duplication rights are stripped. The
privileged bootstrap is not granted to a guest or regular user process.

nxinit registers one service at a time with the protocol declared in
system/include/api/nxmanage.h. The manager verifies the kernel-stamped PID
against its currently tracked init child, validates the version, the stable
slot, the executable tree (/sys/bin or /sys/services only), arguments and
registry-key namespace, and issues a kernel-stamped ACK before nxinit
continues to the next dependency. A malicious sender cannot forge the
manager principal or request arbitrary /sbin execution through this door.

All actual child processes are spawned by nxmanageDD as ROOT-level
processes. Real process exit/wait semantics determine whether a lock
remains held, a one-shot dependency completed, or a restart needs delay.
The manager keeps bounded per-slot state/generation and restart backoff.
Each named service is published under system.manage.service.NAME with one
PID:generation:mode:status record. system.manage.pid, init_pid,
numeric slot compatibility entries and optional srv.* keys remain.
The registry mutation provider rejects ROOT access to machine-only
system.boot, system.manage and system.service namespaces. On death, live PID publication is cleared
until a new process generation starts. No raw kernel pointer is transmitted
across a trust boundary. For larger future payloads, use an NXOLMO-style
typed capability-masked zero-copy buffer lease (object, generation,
offset/length, rights, namespace, commit and revocation fence), not a
bare host pointer. Such larger zero-copy leasing is not yet implemented.

nxinit is reduced to service policy and config parsing; it no longer
contains the old hardcoded per-service status/respawn condition chain,
macro spawn queue, or restart timer. The existing headless nxshell -c
mechanism runs the test runner only in mdebug and never claims another
interactive keyboard window.

## Service/extension directory standard

- kernel/user/extension/* : NX-CORE-owned source compiled as user-mode
  ELFs and installed under /krnl/extension with MACHINE-only authority;
  never directly linked into the kernel binary.
- user/sbin : privileged initializers, installed at /sbin. Only the kernel
  machine bootstrap authority can request their execution.
- user/sys/services : dedicated service executables, installed at
  /sys/services, ROOT process authority, MACHINE-only writable binaries.
- user/sys/bin : commands and graphical programs. nxexec and nxpax
  are command-only; nxexecd and nxpaxd are dedicated /sys/services server
  executables sharing the canonical resolver or SDK protocol rather than
  introducing duplicate implementations. nxroleprobe is a mdebug-only
  ROOT capability regression command.
- system/lib/extensions/services : SDK/client-side service library code,
  not a second executable service tree.
- user/bin : normal applications and real regression binaries.

## Qualification

Actual object contract mirror and SHA-256 snapshot must match. The changed
Power12 gate must have zero findings and the complete strict gate must
remain an independent release gate. Verify actual builds and NXADB shells
for amd64 GRUB BIOS and aarch64 GRUB UEFI; check captest negative rights,
private name denial, process ownership, boot PID order, real VFS manifests,
one-shot completion, 13 test runner cases and ROOT nxroleprobe in mdebug,
service lifecycle,
NXPAX diagnostics, timerdiag and full UART warnings/errors.

The kernel callback timer, cross-host consistency, service crash-injection
SMP stress, loss/backpressure accounting, source-wide libc function coverage
and strict project-wide Power12 remain mandatory independent qualifications.
A successful compile or boot does not prove them. Evidence must be recorded
only after execution, not inferred from code or design.
